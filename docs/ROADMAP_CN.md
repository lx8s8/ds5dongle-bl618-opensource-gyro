# 功能新增与优化清单

整理日期：2026-11-14（北京时间）。基于当前 G1 代码核查；下表是后续建议，未把这些建议作为新功能实现。

建议先完成稳定性与真机验收，再做“每档独立参数 + 手柄直接操作”，随后改善体感手感。优先级表示建议顺序，不代表已经排期；工作量仅表示相对复杂度，不是工期承诺。

## 当前已经具备

| 能力 | 当前实现与边界 |
| --- | --- |
| 固件体感映射 | 鼠标 / 右摇杆；计算在接收器，关闭网页后继续生效；默认关闭 |
| 自定义启用条件 | 按住、长按、按一次切换、按住暂停；L2/R2 阈值、自定义按键组合、触摸、Edge Fn / 背键 |
| 手柄切档 | Edge 原生 Fn 档位决定是否启用；普通 DualSense 可绑定接收器两档，用 Create + 左/右切换 |
| 参数调节 | 独立 XY 灵敏度、轴反转、yaw/roll 选择、微动死区、平滑、速度加速、右杆反曲线与叠加/替换 |
| 标定 | 工厂校准数据、手动静止校准、移动拒绝、断连清除当前手柄零偏 |
| 网页工具 | WebHID 设置与调试、原始按键学习、JSON 导入/导出、RAM 应用/Flash 保存、曲线与 CSV 导出 |
| 自动构建 | GitHub Actions 已实际通过三种板型 × FS/HS 六个版本；含刷机文件、校验和与构建来源；`v*` 标签触发 Release 草稿 |
| 验证边界 | 主机测试、协议与描述符检查、模拟网页和云端编译已通过；真实接收器、手柄及游戏联调待做 |

目前**只有一套体感参数**。配置档绑定是“允许哪些档位开启体感”的掩码，并不是每个档位都拥有独立的灵敏度、启用键和输出方式。普通 DualSense 已能用自定义组合键切换体感开关，不必每次打开网页。

## P0：先验证可靠性

| 编号 | 项目 | 当前依据与建议 | 验收目标 | 工作量 |
| --- | --- | --- | --- | --- |
| 01 | 真机验收矩阵 | 覆盖 DualSense / Edge、三板型、FS/HS、Windows / Linux；先验证默认关闭时的原有透传，再开启体感 | 校准、长按 L2、Fn 档位、背键、保存重启、换手柄、断连恢复全部可复现；音频/触觉并发不产生明显卡顿；记录设备和固件版本 | 中，需硬件 |
| 02 | 统一旧控制命令的任务归属 | 新增体感 `0xFC` 已经在 USB 中断入队、由 `usb_task` 处理；旧 `0xF6/0xFB` 仍在回调直接修改配置，`0xFB/0x05` 还会调用持久化切档函数。建议统一命令队列、快照、参数校验和成功/失败回执 | 配置写入与报告处理不交叉修改同一份数据；中断不执行 Flash；错误参数、保存失败和队列满可诊断；兼容已有网页协议 | 中 |
| 03 | 切档持久化与配置恢复 | `remap_switch_profile()` 每次调用持久化接口。建议 RAM 立即切换，持久化延后合并或显式保存；相同配置避免重复保存，补充配置版本迁移与损坏回退 | 连续切档不阻塞输入；重启档位策略有明确说明；断电/写失败后可恢复有效配置，并报告保存结果 | 中 |

02、03 是代码路径审查发现的改进点，尚未通过硬件复现卡顿或数据损坏，不能当作已证实的现场故障。相关代码见 [`usb_gamepad.c`](../src/usb_gamepad.c)、[`remap.c`](../src/remap.c)；新增体感命令实现见 [`gyro_runtime.c`](../src/gyro_runtime.c)。

## P1：最值得新增的日常能力

| 编号 | 项目 | 建议行为与收益 | 前置条件或验收重点 | 工作量 |
| --- | --- | --- | --- | --- |
| 04 | 每档独立体感配置 | 先提供 4 套完整接收器配置，每套保存开关、输出方式、灵敏度、启用条件、曲线等；Edge Fn 档位可绑定其中一套，普通版用快捷键选择，后续再评估 8 套 | 这是对现有启用掩码的升级；接收器档与手柄原生 Profile 分开管理；协议/Flash 需迁移；切档清空旧鼠标积压和临时状态 | 中至大 |
| 05 | 统一手柄操作动作 | 在现有自定义体感开关上，增加“上一档/下一档、直达某档、开始校准、按住精细瞄准”等动作绑定；支持单击/双击/长按，并说明原按键是否透传 | 避免与 Create + 方向键、游戏输入冲突；只在组合成立时消费还是始终屏蔽，需让用户明确选择；常用操作无需开网页 | 中 |
| 06 | 扳机滞回与 ADS 双灵敏度 | 当前只有单一阈值。增加启用/释放双阈值，减少临界抖动；支持 L2 瞄准时降低灵敏度，松开恢复普通灵敏度 | 例如超过 70/255 启用，低于 55/255 才关闭；长按计时与 toggle 状态一致；保持 L2 原 ADS 功能 | 小至中 |
| 07 | 更清晰的状态反馈 | 在现有板载灯切档闪烁上，增加可选灯效/短震动，提示体感开关、当前档位、校准成功或失败 | 给游戏原生灯效和触觉保留优先级；可关闭提示；不让提示本身干扰瞄准或校准 | 中 |
| 08 | 自动静止零偏校正 | 保留工厂与手动校准，增加可选的可靠静止检测和缓慢零偏更新，改善长时间使用的温漂 | 慢速跟枪不能被学习为零偏；结合角速度波动和加速度；每次连接独立管理，先以保守策略验证 | 中至大 |
| 09 | Player Space / 重力参考 | 当前只能选择固定本地 yaw 或 roll。增加 IMU 重力融合，让握持角度变化时仍能按接近玩家习惯的方向转动视角 | 先统一坐标、单位与时间步长，再测 CPU/RAM；保留 local 模式；重力参考不能提供无漂移的绝对航向 | 大 |
| 10 | 右杆调参向导与兼容预设 | 在现有逐轴反曲线上，增加满杆转速测量流程、径向死区/曲线选项、游戏参数说明和可复用模板 | 说明游戏内灵敏度、死区、加速的对应设置；分别测微瞄、斜向和大幅转身；不承诺摇杆能超过游戏最大转速 | 中 |
| 11 | 延迟与负载可观测性 | 增加传感器/蓝牙间隔分布、可检测的丢包或异常间隔、处理耗时、USB busy、队列深度、Flash 耗时等计数，网页展示并导出 | 当前网页约 10Hz 采样不能证明端到端延迟；先记录分位数和音频负载，再决定是否优化滤波、数学运算或快照拷贝 | 中 |
| 12 | 自适应微瞄滤波 | 现有一阶平滑可用；可增加小动作较稳、大动作低延迟的速度分段滤波或 tightening 参数 | 用固定输入回放和真机盲测比较抖动、阶跃延迟与快速甩动；避免仅靠加大死区吞掉细小动作 | 中 |

每档独立配置完成后，可以提供以下**建议模板**，不是当前已有四套参数：

| 档位 | 建议用途 | 体感策略 |
| --- | --- | --- |
| 默认 / 档 1 | 普通游玩 | 关闭 |
| 档 2 | FPS 瞄准 | 按住 L2，鼠标输出，独立瞄准灵敏度 |
| 档 3 | 不支持混合键鼠的游戏 | 按住 L2，右摇杆输出，单独游戏曲线 |
| 档 4 | 精细操作 | 自定义背键/组合键启用，较低灵敏度 |

Edge 可通过原生 Fn 组合切到绑定档；普通 DualSense 通过固件快捷键切档。两者都可把网页作为初次配置工具，日常使用直接操作手柄。Edge 的原生按键/摇杆 Profile 仍由索尼原有工具管理；这里扩展的是接收器保存的体感配置。

## P3：核心体验稳定后再扩展

| 编号 | 项目 | 价值与取舍 | 工作量 |
| --- | --- | --- | --- |
| 19 | 更多轴路由与体感转向 | 增加左摇杆输出、三轴到双摇杆的路由、基于重力的角度保持；适合赛车、飞行与其他操作方式，需要独立的中位/最大倾角设置 | 大 |
| 20 | Flick Stick / 快速转身 | 摇杆快速改变水平朝向，体感负责精瞄；先在鼠标模式验证现实角度标定。与右杆输出的“超过满杆部分延后释放”是不同机制，二者都需要明确取消与积压上限，避免松手后继续转 | 大 |
| 21 | 扩展其他手柄与输出协议 | DS4 / Switch 等需各自的输入解析、工厂标定、按钮能力与连接测试；XInput 等额外输出协议也应单独评估，不能只换 USB 名称 | 大 |

扩展第三方背键时，应先确认手柄是否有独立上报位；只复制普通按钮的背键不能在接收器侧凭空区分。用户当前需求中的 Fn 切档指 DualSense Edge，本清单优先围绕它与普通 DualSense。

## 参考实现的选择

以下项目适合参考不同层面，不建议整套搬入 BL616 固件。实际引入代码时再核查对应提交、许可与资源开销。

| 参考 | 建议借鉴 | 与本项目的关系 |
| --- | --- | --- |
| [ps5-gyroaim](https://github.com/jmelovich/ps5-gyroaim) | 参数语义、三轴路由、右杆曲线反演、速度/保持角度两种模式、分段平滑 | 继续作为功能与交互参考；其 PS5 运行时注入方案不属于接收器架构 |
| [GamepadMotionHelpers](https://github.com/JibbSmart/GamepadMotionHelpers) | 重力融合、Player Space / World Space、自动与手动校准 | 优先用于 08、09 的算法评估；它是 C++ 头文件库，需评估直接集成或以当前 C 引擎重写对应计算 |
| [JoyShockMapper](https://github.com/JibbSmart/JoyShockMapper) | Flick Stick、现实角度标定、按键模式切换、临时灵敏度层、配置设计 | 适合参考 05、06、10、20；其 PC 运行环境和主机驱动依赖无需全部移植 |
| [Linux hid-playstation](https://github.com/torvalds/linux/blob/master/drivers/hid/hid-playstation.c) / [SDL PS5 驱动](https://github.com/libsdl-org/SDL/blob/main/src/joystick/hidapi/SDL_hidapi_ps5.c) | 报告字段、传感器单位、工厂标定、设备兼容 | 继续用于协议核查，减少不同手柄固件版本带来的误解析 |
| [RKLAB 配置/更新](https://test.rklab.cn/bl616/#config) / [手柄测试](https://test.rklab.cn/dstester/) | 配置分区、输入可视化、更新流程 | 在现有中文 WebHID 页上完善体验；网页能力与实际固件/Boot2 能力分别验收 |

建议的首轮实施范围是 01–07 和 11：先验证并修整配置路径，再让独立配置档、快捷操作、扳机稳定性与状态反馈形成完整体验。08–10、12 涉及手感和算法，适合在可测量的输入链路上逐项比较。

相关文档：[当前体感使用与协议](GYRO_CN.md)、[自动编译与固件下载](CI_CN.md)。
