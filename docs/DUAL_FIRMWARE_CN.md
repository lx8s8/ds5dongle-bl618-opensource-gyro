# 双固件可行性核查

核查日期：2026-11-14。目标是在上游原版与本项目体感固件之间选择启动，分别更新，切换时不重新编译、不重复刷写主程序。当前尚未实现或写入设备。

## 容量与启动基础

当前信海 BL616 为 4 MiB Flash。仓库分区表中，`FW` 已声明两处地址：

| 区域 | 起始地址 | 最大长度 |
| --- | --- | --- |
| A | `0x10000` | `0x200000`（2 MiB） |
| B | `0x210000` | `0x168000`（1.40625 MiB） |

上游 v3.24 的 LCTech FS／HS 主程序均为 837248 字节，可放入 B 区；本项目主程序也能放入。容量可容纳两份当前镜像，但分区表中的 `mfg` 与 B 区重叠，不能把这段地址当作未经核查的空闲存储。

SDK 的 `bflb_boot2_update_ptable()` 能切换分区活动索引；[官方 OTA 示例](https://github.com/bouffalolab/bouffalo_sdk/blob/master/examples/wifi/sta/wifi_ota_by_http/README.md) 说明 Boot2 依据活动分区启动应用。这提供了 A/B 基础，不等于已经完成了独立双固件管理。

## 软件双向切换的缺口

本项目可以增加专用命令来选择另一槽并重启。但切到未经修改的上游固件后，本项目的专用命令不再运行。公开 v3.18 源码的配置接口仅有设置、保存、保存重启等命令；目前未核实 v3.24 二进制存在可用的“选择另一个启动槽”命令。不能在配置页放一个无法从上游返回的切换按钮。

完整方案至少需要：

1. 验证当前 Boot2 对两个独立镜像的启动、校验、活动索引与失败恢复行为，确认不会将备用镜像搬移覆盖主镜像。
2. 为上游运行期间提供可靠返回入口，例如经过验证的按键启动选择器，或上游提供的切槽命令。自定义启动器需要单独开发和验收；不能仅由网页模拟出来。
3. 核对两版 SDK 的持久存储布局、配置结构与配对记录兼容性，必要时隔离两套设置，保留共用配对数据必须实测。
4. 分别记录每槽的来源、板型、版本、长度和哈希；更新只写目标槽，校验成功再切换。上游更新从其 Releases 下载原始包并验证，不要求重新编译。
5. 验证更新失败、断电、两槽之一损坏、软件重启和手动恢复路径。

“软件缓存两份镜像，选择后串口重刷”可以绕过源码缺失，但每次切换仍会刷写，达不到双槽直接切换的目标。当前不改动用户设备的 Boot2、分区表或备用槽；体感稳定性修复仅更新现有主程序。

源码未迁移的直接证据见 [上游作者回复](https://github.com/sqlCRT/ds5dongle-bl618-opensource/issues/10#issuecomment-5742496052)：二进制继续发布，源码暂缓更新。因此不能通过合并 v3.24 标签来获得修改上游切槽入口的源码。
