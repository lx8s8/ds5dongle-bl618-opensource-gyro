# BL616 / BL618 固件陀螺仪映射 G1

这一分支在已有 DualSense USB 透传路径中增加体感处理。运算运行在接收器固件，网页只负责设置和观察；应用后关闭网页仍生效。默认关闭映射，避免首次连接就移动电脑光标。

当前完成了源代码与主机模拟验证，尚未完成 BL616 / BL618 编译和真实手柄联调。请先阅读下文的验证边界。

## 日常使用方案

### DualSense Edge：用 Fn 配置档控制体感

可以指定原生配置档开启体感，例如：

| 手柄档位 | 固件行为 |
| --- | --- |
| Fn + △（默认档） | 关闭体感映射 |
| Fn + □ | 开启体感映射 |
| Fn + × | 关闭体感映射 |
| Fn + ○ | 关闭体感映射 |

网页设置为：

1. 输出选择“鼠标”或“右摇杆”。
2. 启用方式选择“始终启用”。
3. 配置档绑定选择“Edge 原生 Fn 配置档”。
4. 仅勾选 `Fn + □`，点击“应用并保存”。

接收器读取**手柄实际上报的当前档位**，无需在固件中猜测 Fn 组合键。切到未选中的档位时立即清除体感积累位移和切换状态。也可以勾选多个档，或使用“按住 L2”作为所选档位内的第二层条件。

Edge 的按键布局、摇杆曲线等原生档位内容，仍在 PS5 或 PlayStation Accessories 设置。本网页保存的是接收器的体感策略，不会修改手柄原生 Profile。G1 支持“哪些档位启用体感”，这些档位共用一套体感参数；每档不同灵敏度可在后续扩展中增加。

### 普通 DualSense：两种更方便的开关

**方案 A：接收器两档切换。** 配置档绑定选择“接收器映射档（通用）”，仅勾选“接收器档 2”，启用方式选择“始终启用”。`Create + ←` 进入档 1（普通操作），`Create + →` 进入档 2（体感操作）。已有的两套按键映射也同时切换；板载灯分别闪一次 / 两次。组合键在固件内被消费，避免整组快捷键传进游戏。

**方案 B：自定义快捷键开关。** 启用方式选择“按一次切换开关”，扳机条件选择“无”，选择 `Create` 和 `R3`，勾选“需要所有选中的按键”，长按延时设为 300ms。持续按住组合键只触发一次，释放后再次按下才关闭。若选“屏蔽启用键原始输出”，被选中的按键即使单独按下也会被屏蔽，因此需要保留它们在游戏中的用途时不要勾选。

网页也能直接开关：把“输出方式”改为“关闭体感”并应用即可。不要求一直打开网页，也不要求安装 PC 常驻程序。运行中的切换开关状态在重连、长时间丢包、重新应用设置或切换配置档后重置为关闭；保存的是启用策略，不是临时开关状态。

### 瞄准时按住 L2

点击网页“按住 L2”预设再应用。默认阈值为 64/255，松开立即停止；“长按 L2 · 300ms”预设会等待持续按压 300ms 才启用。L2 的原始 ADS 输入默认保留。阈值可调，R2 同理。

### 背键与其他启用源

可选普通按键、方向键、触摸板点击、任一手指触摸、Edge 左/右 Fn 与 L4/R4 背键，也可组合。按键条件可以“任一个”或“全部”；扳机阈值条件与按键条件之间是 AND。

Edge 背键使用物理独立位，不依赖它在手柄 Profile 中映射成什么普通按键。如果手柄内部将背键同时映射成 Cross，该 Cross 仍然会到达游戏，除非另行配置屏蔽或更改原生 Profile。普通 DualSense 没有独立背键；其他品牌或改装背键能否独立识别，取决于设备是否提供独立上报位。

## 打开网页

在仓库根目录运行：

```sh
python3 -m http.server 8765 --bind 127.0.0.1 --directory web
```

用桌面 Chrome / Edge 打开 `http://127.0.0.1:8765/`，连接 USB 接收器。网页有设置、实时调试和固件更新说明三个区域，无外部脚本依赖。连接时检查 0xFC / 0xFD 描述符，避免把原装直连手柄误当成支持此扩展协议的接收器。

- “应用到固件”只改 RAM，立即生效。
- “应用并保存”先应用，再写入独立 Flash key `gyro_cfg_v1`，断电保留。
- “恢复默认”在 RAM 关闭体感；保存后才永久生效。
- JSON 导入只填表单，需应用才写入设备。
- 调试页显示原始按键、原始传感器、校正后角速度、实际 USB 右摇杆、校准状态和当前档位，支持最近 600 个观测点的 CSV 导出。网页以约 10Hz 采样状态，不代表蓝牙/固件处理频率；实际处理跟随收到的手柄报告。

## 映射方式与参数

| 设置 | 实现和含义 |
| --- | --- |
| 输出 | 关闭 / HID 相对鼠标 / USB DualSense 右摇杆 |
| 启用 | 始终、按住、按一次切换、按住暂停；支持 0–3000ms 长按延时 |
| 水平轴 | 本地 Yaw（Y）或本地 Roll（Z）；垂直为 Pitch（X） |
| X/Y 灵敏度 | 每轴独立倍率 0.01–100，支持反转 |
| 鼠标基准 | 0.01–100 counts/°，再乘每轴灵敏度；与游戏鼠标灵敏度共同决定实际视角 |
| 微动死区 | 0–10°/s；二维速度向量减去阈值后平滑收缩到零 |
| 平滑 | 一阶低通时间常数 0–100ms；0 禁用。较大值会增加延迟 |
| 加速 | 按手部角速度在两个阈值之间插值，从 1 倍升至设定最大倍率 |
| 游戏满杆转速 | 用于把目标角速度换算为右摇杆幅度。游戏内满杆转一圈所用秒数为 T 时，填写 360/T |
| 游戏死区/曲线 | 对每轴目标速度做死区和幂曲线的反变换；当前为逐轴近似，不是游戏径向响应的精确反演 |
| 物理右摇杆 | 与体感叠加，或体感启用时被替代；非启用时正常透传 |

鼠标相对位移按**传感器时间差**积分，保留小数残差；遇 USB 忙保留待发送位移，单包限制为 ±127 counts，每轴积压最多 ±2048 counts，超出会丢弃以限制长尾。松手、关闭或离开允许档位清空积压。触摸板与按键鼠标共用一条鼠标发送路径，避免两路输入互相覆盖。

右摇杆输出仍是标准 DualSense HID，**不是 XInput / Xbox 设备模拟**；需要 XInput 的游戏可以继续使用已有 Steam Input 等主机映射方案。右摇杆模拟受游戏满杆速度、8bit 分辨率、轴曲线和混合输入支持限制。鼠标模式通常更适合支持键鼠和手柄同时输入的游戏，具体需实测。

## 标定与时间

1. 优先使用蓝牙握手已缓存的 Feature 0x05 工厂数据，验证跨度、偏置与比例范围后转换为 °/s。
2. 不可用时使用标称 `16 raw counts/(°/s)`；网页明确显示“标称值”。`1024` 是 Linux 归一化后的每 °/s 分辨率，不应直接用作原始 HID 数据换算因子，更不是 raw 数据每 rad/s 的比例。
3. 点击“静止校准”，连续静止 2 秒且至少 100 个样本后计算三轴零偏。要求角速度绝对值不超过 3°/s、窗口内波动不超过 0.8°/s、加速度长度在约 0.9–1.1g；不满足会重新计时。采样按时间加权。
4. 不在瞄准中自动学习偏置，避免慢速跟枪被错误学习为零。校准过程中暂停映射；按键原始输出仍由屏蔽选项决定。
5. 零点和工厂数据仅绑定当前连接，不持久化到其他手柄；新连接重新读取工厂数据，手动零点需再次校准。
6. DualSense sensor timestamp 单位约 1/3µs，使用无符号差处理回绕。传感器或主机接收间隔超过 50ms 时重建处理历史；超过 100ms 无样本时清空体感状态。复位后的第一样本不积分鼠标位移。

本次同时纠正了 `ds5_parse_bt_input()` 的 Y/Z 轴字段，并修复其 32bit 时间戳读取的有符号左移。63 字节原始 IMU 数据继续透传，主机仍可以读取原始体感；若主机侧也启用体感鼠标映射，应避免重复处理。

## 协议与代码组织

- `src/gyro.c/h`：不依赖 SDK 的单手柄处理引擎。
- `src/gyro_runtime.c/h`：Flash、BT 标定缓存、任务内命令、ISR 可读双缓冲快照。
- `src/main.c`：保存原始输入，在内建组合键处理后、普通 remap 前应用体感；断连请求在 USB 任务处理。
- `src/remap.c`：合并鼠标位移与鼠标按键，发送成功后才消费积压。
- `web/`：纯静态页面与固定长度协议编解码。
- `tests/`：主机模拟、描述符解析和网页协议测试。

已有 `config_body` 和 0xF6–0xF9 / 0xFB 布局未扩展；0xFC 为体感配置，0xFD 为只读状态。两者 Feature data 均为 63 字节，Report ID 不包含在 data 中。DS / DSE 描述符分别为 345 / 461 字节。键盘/鼠标复合接口始终枚举，便于运行时开启鼠标，端点周期在 FS / HS 下均为 1ms。

### 0xFC SET

data[0] 为命令，data[1] 为客户端序号（建议 1–255），其余补零到 63 字节。

| 命令 | 行为 |
| --- | --- |
| 1 | data[2..41] 为 40 字节配置；验证全部字段后原子应用，否则不修改现有设置 |
| 2 | 保存当前配置到 Flash；不保存当前连接的零偏 |
| 3 | 开始静止校准 |
| 4 | 恢复默认到 RAM（关闭体感），不自动写 Flash |
| 5 | 清除手动零偏，保留工厂标定 |

USB ISR 仅排队，参数验证和 Flash 都在 usb_task。读回 0xFC 的 data[40]=已处理命令，data[41]=结果（0 成功、1 参数/命令无效、2 Flash 失败），data[42]=序号，data[43]=能力位（mouse/stick/Edge sources/profile binding）。网页等待匹配回执后才报告成功；队列满等情况超时，不伪报成功。

### 40 字节配置 v1

所有多字节整数为 little-endian；整数定点编码，无未对齐的浮点访问。

| 偏移 | 类型 | 含义 |
| --- | --- | --- |
| 0 | u8 | 版本 1 |
| 1 | u8 | 输出 0 off / 1 mouse / 2 right stick |
| 2 | u8 | 激活 0 always / 1 hold / 2 toggle / 3 hold off |
| 3 / 4 | u8 / u8 | 扳机 0 none / 1 L2 / 2 R2；阈值 1–255 |
| 5 | u8 | flags：bit0 invertX、bit1 invertY、bit2 suppress、bit3 requireAll |
| 6 / 7 | u8 / u8 | 水平轴 0 yaw / 1 roll；平滑 ms |
| 8 | u16 | hold ms |
| 10 / 12 | u16 / u16 | X/Y 灵敏度 ×100 |
| 14 / 16 | u16 / u16 | 鼠标 counts/° ×100；微动阈值 °/s ×100 |
| 18 / 20 / 22 | u16 各一 | 最大转速 °/s；游戏死区 ×1000；曲线指数 ×100 |
| 24 / 26 / 28 | u16 各一 | 加速倍率 ×100；加速起/终速度 °/s |
| 30 | u32 | 按键 mask，bit 0–23 见 `gyro.h` / `web/protocol.mjs` |
| 34 | u8 | 摇杆融合 0 add / 1 replace |
| 35 / 36 | u8 / u8 | 档位源 0 不限 / 1 Edge 原生 / 2 接收器；允许的档位 bitmask |
| 37–39 | u8 各一 | 保留，必须为零 |

Edge bit0–3 = Fn+△ / □ / × / ○；接收器 bit0–1 = 档 1 / 2。

### 0xFD GET：63 字节状态

| 偏移 | 数据 |
| --- | --- |
| 0 / 1 / 2 / 3 | 版本；flags（有新鲜输入/激活/校准中/已校准/有工厂标定）；输出模式；校准进度 % |
| 4 | u32 样本时间差 µs |
| 8 / 14 | i16×3，原始 gyro / accel |
| 20 / 32 | i32×3 校正后 gyro °/s×100；i32×2 滤波后目标速度 °/s×100 |
| 40 / 42 | u8×2 处理后右摇杆（remap 前）；i16×2 待发鼠标 counts 的整数部分 |
| 46 / 50 | u32 原始按键 mask；u16 校准样本数 |
| 52 / 58 | i16×3 当前手动零偏 °/s×100；u32 累计样本数 |
| 62 | 低四位：Edge 原生报告档位 1–4 / 0 未知；bit4–5：接收器档位 0/1 |
