# DS5 控制中心：本地运行与桌面打包

更新：2026-11-15。控制台是本地静态网页，通过 WebHID 直连接收器。无需账号、数据库或远端服务器；连接硬件需要桌面 Chrome / Edge，Safari / Firefox 不支持此接入方式。

## 打开方式

- 普通用户：下载对应系统的 `DS5-Control-Center-windows-amd64.zip`、`DS5-Control-Center-macos-arm64.zip` 或 `DS5-Control-Center-macos-x86_64.zip`，解压后双击 `.exe`／`.app`。这是原生绿色程序，网页嵌入程序，不需要安装 Python、Rust、Node 或额外运行库；仍需已安装桌面 Chrome／Edge。底部“退出本地工具”关闭服务。
- 源码用户：`DS5-Control-Center-source.zip` 包含网页与源码启动器。已有 Python 3 时，macOS 双击 `启动控制中心.command`，Windows 双击 `启动控制中心.cmd`；也可执行 `python3 desktop/launcher.py`。旧版的 `portable.zip` 指这个源码包，现已改名以免混淆。
- 网页可独立使用：在 `web/` 目录运行 `python3 -m http.server 8765 --bind 127.0.0.1`，访问 `http://127.0.0.1:8765/`。不要直接双击 `index.html`，模块加载与硬件权限需要合适的来源。

本地启动器只监听 `127.0.0.1`，仅公开随包网页；浏览器向 GitHub 查询更新，不上传配置、输入报告或配对信息。同一接收器同时保持一个已连接的配置客户端；同页内的 Feature 请求统一排队。无网络时仍可设置接收器、导入导出配置与测试手柄，Release 检查需联网。若默认端口被占用，启动器会选空闲端口，新的来源需要重新授权 HID。

点击“连接接收器”后，只有一个已授权且支持体感报告的接收器时直接复用授权；首次使用或存在多个接收器时显示设备选择框。刷新页面不会自动连接或执行测试，也不会自动切换标签。

正式固件保留 Sony 的 `054C:0CE6`（DualSense）／`054C:0DF2`（DualSense Edge）、对应产品名和原生报告。`T` 后缀与 `1209:0001` 是此前隔离 macOS HID 驱动问题的私下测试身份，部分游戏及配置软件会将其当作普通 HID，不能作为日常兼容方案；连接这种设备时网页会持续提示。Release 打包拒绝发布该测试身份。正式身份下，本机 macOS 的复合鼠标输出仍待解决，不能以诊断身份下鼠标可用代替验收。

测试页为双栏布局，左侧手柄总览与扳机行程常驻，右侧六个标签切换测试内容；不会通过锚点跳转整页。

体感“应用”只写当前编辑档和全局，体感“保存到设备”提交全部四档草稿与全局。接收器和普通映射有独立的保存按钮与 JSON 文件，互不静默覆盖。手柄图点击普通按键可定位映射行，Fn/背键可定位体感启用按键。

四种启用模式中，“按一下开启 / 再按关闭”是按键边沿切换；“按住启用”仅在所选条件成立时启用。长按延时可叠加在按住模式。普通按键支持任一个或全部组合，扳机与按钮条件是 AND。可绑定的“任意按键”指固件可识别的手柄输入，不能让未运行的电脑键盘状态凭空进入接收器。

曲线是现有固件算法的单轴稳态预览：鼠标显示 counts/s，右杆显示归一化输出；分别绘制 XY 与 ADS。二维死区、平滑的时间响应及游戏内转向还受实际输入和游戏设置影响。当前曲线使用幂指数等固件参数，不提供任意自由控制点曲线、Player Space、Flick Stick 或超出当前协议的路由。

G2.3 修正右杆输出：游戏死区补偿按二维向量幅度处理，避免微小的另一轴噪声也被单独抬到最低输出；微动死区采用起动／回落滞回，进入静止区立即回中；大幅转动减少滤波，明显反向清除旧方向历史。零点校准仍需手柄静止完成，参数不能替代校准。Yaw／Roll 是不同的物理转动轴，反转只改变方向，不改变转动轴。

新连接默认编辑当前生效档，主动选择其他编辑档时会标明与当前生效档的区别。Yaw 用于手柄平放时的左右平转，Roll 用于像方向盘一样左右侧倾。当前右杆映射按转动速度工作，保持偏转角度后停住会回中；角度保持和姿态自适应模式尚未实现。取轴与成熟项目的对照见 [体感取轴分析](GYRO_AXIS_ANALYSIS_CN.md)。

“摇杆测试”下方可展开“FPS 视角预览（模拟）”。它使用实际 USB 右杆和生效档的满杆转速、死区、曲线模拟游戏视角；回中会停止转向并保持新视角，不会恢复原朝向。它不测量真实游戏延迟，游戏参数与配置不一致时，速度也不会与实际游戏相同。

“手柄测试 → 触控体感”曲线下方提供静止校准、数据 CSV 和诊断 JSON。诊断包含最近 30 秒实际 USB 输入及屏幕绘制时刻、最近读取的设备配置和异步 Feature 遥测，均通过当前网页连接采集，不另开 HID 客户端。USB 输入最多保留 32768 条，绘制最多 4096 条；超过数量或时间窗口的旧数据会移除。传感器时钟每微秒 3 tick、32 位回绕；这份记录可比较相对积压与绘制间隔，不能测绝对端到端延迟。CSV 的 `stick_x/y` 为固件遥测输出，诊断 JSON 的 `capture.inputs` 才是主机实际收到的 USB 报告。

震动默认测试 1 秒；停止按钮、离开测试页、页面转后台或主动断开时解除震动/扳机测试。灯光和音频测试会真的修改手柄当下状态，持久设置请在接收器配置页操作。浏览器/系统崩溃无法保证最后一条解除指令送达，此时拔插接收器恢复。

## G2.4RC4：宏与保存的静止校准

“宏与绑定”提供 16 个设备槽位，每个最多 640 步，支持手柄键（含 Edge Fn／背键）、键盘键及修饰键、鼠标按钮与滚轮。可设置单次／指定次数、按住循环、按下开启再按关闭；同时运行一个宏。16 条触发绑定可选择任意物理按键或组合键，设置按下、松开、长按、双击、三击，并限定四个体感配置中的某几档。长按与连续点击时间可调整；保存绑定前按住的键须先松开再按，不会因为保存设置而立即播放。

选择槽位后编辑步骤，点“保存此宏”；“测试已保存的单次宏”播放设备里的版本。循环宏用绑定键测试，“停止并释放按键”可随时取消。宏和绑定分别保存，离开网页或换到 Windows 后仍在接收器运行。切档、蓝牙断连或超过 100ms 无输入会取消宏并释放合成按键；物理摇杆继续透传。键盘、鼠标与已有映射合并输出，不以宏的松开指令清除仍按住的物理键。

“录制手柄按键”捕获浏览器收到的 USB 按键边沿，包含当前普通映射后的结果；不记录摇杆／扳机模拟行程或触摸轨迹，键鼠步骤通过编辑器添加。录制期间临时暂停设备宏，停止后恢复；网页消失时约 3 秒心跳超时恢复。浏览器后台节流可能影响录制时间，录好后检查步骤和等待时间再保存。支持 JSON 和 MAC1 二进制导入导出；MAC1 支持上述输出子集，不支持第三方配置库或尚未实现的模拟动作。

文件使用 media 分区的 `/gyro/` 独立目录，上传通过长度、步骤和 CRC 检查，保存采用临时文件及原子重命名。读取不会初始化存储；首次保存仅允许格式化完全空白的分区，不会格式化无法挂载但已有数据的分区。空间不足或 I/O 失败会报错并保留旧文件。宏模块本身不改分区表，已有正常接收器升级只更新主程序。完整烧录包仍含标准 Boot2 与分区表，已安装双固件时须使用专用迁移／恢复流程；从其他项目迁移前仍需导出它的配置。

静止校准成功后保存上次测得的零偏；只有手柄标识和工厂标定同时匹配才恢复，其他手柄不会套用该值。“清除校准”也会清除这份保存值。现有四档速度、曲线、死区、反转和激活配置保持原协议。旧 G2.3 没有宏接口，需要更新固件才能使用；只换网页无法增加设备端宏。

“导出诊断”增加 `receiverTrace`：约 500ms 一组映射前输入／输出对照，以及最近 24 个连接、断连、看门狗和原生配置写入事件。它能帮助区分物理输入、固件输出和游戏接收，不等于完整高频采样或真实游戏延迟；日志保存在 RAM 中，接收器断电会丢失。若再次发生摇杆失效，尽量在关闭手柄前导出。

本次移植了 DS5DongleRE 的连接对象生命周期处理、宏格式／调度与存储思路、手动零偏保存，并增加了本项目的校验、取消和协议适配。还修复了 Edge 配置预取过早宣布就绪的问题。没有替换 Sony／Edge 身份或改用对方的全局体感配置。Apex 的输入失效尚未复现确认；新增功能在真机、Windows 游戏和 Mac 键鼠接口上的验收仍需完成。

## 双固件配对同步管理器

“固件与更新 → 双固件切换与维护 → 配对同步管理器升级与恢复”用于给已安装的双固件设备升级管理器。先选配对同步管理器包，读取设备并下载 `.ds5backup`，确认保存后重新选择该文件，再执行升级。备份与芯片 ID 绑定并包含配对密钥，请妥善保存、不要上传。首次安装时选用配对同步包也需要这一确认步骤。

如果管理器升级或安装中断，请按住 BOOT 插入接收器，在同一面板选择该备份并执行恢复。升级恢复仅回写管理器和扩展区；首次安装恢复会将整个闪存还原到安装前状态。其他区域若在升级备份之后发生变化，升级恢复会拒绝覆盖。实机已验证特定写入点拔电和指定管理器载荷扇区恢复，并不代表任意中断位置均已实机验证。

## 蓝牙配对管理

更新后的体感固件在“接收器配置 → 蓝牙手柄配对”提供已配对列表、搜索配对和删除单个配对。搜索或删除当前手柄时会先断开蓝牙；进入管理功能后，该次运行期间保持 USB 可见。删除操作有确认提示，只作用于当前体感固件的数据区。上游原版没有本功能的网页命令。安装支持配对同步的管理器后，切槽前会将当前配对记录同步到目标槽；旧版管理器仍保留独立配对。

网页刷写和本地构建默认选择 HS；如线路或设备不支持，可手动选择 FS。HS / FS 与接收器的 USB 报告频率为不同设置；更改回报率后需要保存并重启才能重新枚举。

## Windows 使用与双固件原型

已保存的体感档、Fn 绑定、接收器设置和映射在接收器启动时加载，换电脑不需要常驻本工具。正常插入并连接手柄后，映射由接收器执行；游戏对 PS 手柄的支持和 Windows 真机兼容性仍需各自验收。

G2.4（LCTech FS 与 HS）增加在已安装独立启动管理器时进入管理接口的命令；当前普通单固件设备仍不包含启动管理器。更新页“双固件切换与维护”除实验性 HID 切槽外，现已支持通过 Web Serial 读取整片 4 MiB 备份、首次安装双固件（写入前自动下载备份）、按槽位更新镜像以及使用原始备份卸载恢复单固件。启动管理器、双向跳转与第三方配置软件仍待真机验证，不将主机／模拟测试通过称作完成真机验收，操作规则见 [双固件说明](DUAL_FIRMWARE_CN.md)。

## 网页刷写固件

需要桌面 Chrome / Edge（Web Serial），不需要 Python、Dev Cube 或服务器。

1. 在“固件与更新”页下载匹配板型和 USB 速度的 `ds5dongle-*.zip`（桌面启动器可直接点击一键下载填入，无需解压）。
2. 在“网页刷写固件”确认包内容。含 `SHA256SUMS` 的本项目包会逐个校验 Boot2、分区表和主固件并显示提交号；不含 `SHA256SUMS` 的上游包会校对 BL616 启动头、分区布局并提供 FS/HS 变体选择。
3. 按住接收器上的 BOOT 键插入 USB，松开；点击“开始刷写”，选择 Bouffalo 串口设备（VID 349B）。Ai-M61 等经板载串口桥连接时选对应串口。
4. 流程：读取启动信息，先读取启动头、分区表与双固件记录检查布局；由版本列表下载且来源明确的固件会在双固件设备上更新对应槽，手动选择且来源不明的包会停止并提示使用分槽维护，识别 Flash，擦除并写入所选区域，每个文件写后读回 SHA256；全部一致才清除启动标记并复位。任何一步失败都不会复位，重新进入 BOOT 模式即可重试。

“完整”写入 Boot2、分区表和主固件（首次安装或恢复），“仅主固件”只更新 `0x10000` 起的应用。只擦写所选区域，不整片擦除。启用签名或加密的芯片会被拒绝。已安装双固件启动管理器的设备不要完整刷写。通信协议基于 Bouffalo 开源的 bflb-mcu-tool（Apache-2.0），在 ROM 下载模式下直接写 Flash，不需要 eflash_loader。尚未在本项目全部板型真机验收，出现问题请回退到 Dev Cube 方式。

macOS 应用尚未做 Apple Developer ID 签名和公证；Windows 应用尚未做 Authenticode 签名。跨系统产物由 `Control center` Actions 在 Windows、macOS Apple Silicon 和 Intel 运行器分别构建，并逐个平台实际启动原生服务、校验内嵌网页、来源限制及退出。ZIP 名称包含架构。

## Tauri 是否可行

可以，但需要 Rust 原生 HID 接入，不能只给此网页套一层窗口。Tauri 的 Windows 使用 WebView2，macOS 使用 WKWebView；后者不提供本工具依赖的 WebHID。完整方案应把枚举、足长 Feature、命令排队、输入流、关闭恢复等移到受限的原生 `hidapi` 桥接，前端复用当前协议/表单/可视化，并做两端真机验收。串口刷写还需独立实现 BootROM 协议和恢复流程。

本轮交付选择本地服务 + 已安装 Chrome/Edge，直接复用已验证的 WebHID 链路；未把空 Tauri 壳宣称为完整硬件客户端。
